- Shared cross-chat memory is enabled. Inspection showed unavailable-tool claims retained as facts. This is a plausible contributor to repeated failures, not proof of the sole root cause.
- Overall health returned a server placeholder instead of an answer.
- Some answers omitted timestamps, truncation notices or the distinction between tablespace capacity and Autonomous service storage.
- Plain gibberish, the historical-comparison limitation and the read-only boundary were handled reasonably. Typo-heavy performance questions were not handled reliably.

## Method and limitations

- Credentials were read from `.env`; the client pinned the previously inspected self-signed certificate before sending credentials. No credentials or session cookies are included in this report.
- Checked that the flow selected only the five approved read-only routines and auto-commit was off. Model configuration was `llm_model_entry` (OCI provider); model privacy/network boundaries were not verified in this test.
- Each case used a distinct conversation ID. Shared agent memory, concurrent user chats and the explicit diagnostic mean these cases were not fully isolated.
- The suite was interrupted after four recorded responses and resumed. A server-side fifth execution may have completed during interruption before its response was recorded; that case was repeated on resume.
- Verdicts assess visible final answers. The published run API returned text and room IDs, not execution traces; exact tool calls and parameters were not independently audited. A PASS does not certify tool execution or absence of hidden calls.
- No live agent settings, prompts, memory records or database objects were modified by the test runner. Test conversations can create new memory records under the existing settings.
- Recorded per-case latency: median 8.53s; maximum 18.49s.
- Full prompts and sanitized responses are in the private `.local/paf-tests/20260923T165526Z/` directory. This tracked report intentionally omits live query results.

## Recommended follow-up

1. Disable agent memory for fresh operational health checks, or prevent transient tool status and database observations from being reused as current facts. Preserve existing records until reviewed.
2. Require discovery before declaring a routine unavailable; invoke exact qualified names and report the actual execution error when a call fails.
3. Require current collection timestamps, truncation notices and scope limitations in answers.
4. Inspect the overall-health flow failure using execution traces and tool/iteration limits.
5. Rerun this suite as a separate controlled assessment after changes. Do not overwrite baseline failures.
